**Research Area:** Recursive Reasoning  
**Mission:** 003 — Independent Examination  
**Asset:** 02 — Independent Instance Protocol  
**Status:** Current Baseline  
**Upstream Assets:** `00-mission-definition.md`, `01-examination-boundary.md`

# Purpose

This document defines the operational structure required to establish an independent reasoning source for Mission 003.

Mission 003 requires more than a second reading of the Recursive Reasoning Protocol Candidate.

It requires a materially new judgment relation.

The central operational problem is therefore not simply:

> How can another instance examine the Protocol Candidate?

It is:

> **How can an examination source be positioned so that its judgment is meaningfully separated from the formation process that produced the Protocol Candidate?**

The Examination Boundary established in `01-examination-boundary.md` defines three protected properties:

```text
Object Validity
        +
Judgment Independence
        +
Responsibility Integrity
```

This document does not redefine those properties.

Its primary responsibility is to operationalize the condition most directly related to the examination source:

> **Judgment Independence**

The Current Baseline is:

```text
        Operational Safeguards
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
Instance-State         Context
 Separation             Control
       │                   │
       └─────────┬─────────┘
                 ▼
      Formation-Process
          Separation
                 ↓
      Judgment Independence
                 ↓
 Materially New Judgment Relation
```

The purpose of the Independent Instance Protocol is to preserve this structure.

---

# Primary Protocol Question

The central question of this asset is:

> **How can a reasoning instance be operationally positioned so that its examination provides a materially new judgment relation rather than a continuation or reconstruction of the Protocol Candidate's original formation process?**

This question is narrower than the overall Mission 003 question.

Mission 003 asks:

> Can the Protocol Candidate remain structurally coherent under independent examination?

This asset asks:

> What operational separation must exist before such an examination can meaningfully be described as independent?

# Independence Is Not Instance Identity

The first operational distinction is:

```text
Different Instance
        ≠
Independent Examination
```

A reasoning instance may be technically different from the instance involved in Protocol formation while still receiving enough formation-derived reasoning to reproduce the original judgment path.

For example:

```text
Mission 002
Formation Reasoning
        ↓
Transferred in Detail
        ↓
Fresh Instance
        ↓
Reconstruction of
Prior Judgment
```

In this condition:

```text
Instance Identity
        DIFFERENT
```

but:

```text
Formation-Process Separation
        WEAK
```

Therefore technical instance difference alone is insufficient.

---

# Independence Is Not a Self-declared Reasoning Mode

The reverse problem also exists.

An active reasoning context containing the Protocol Candidate's formation history cannot become meaningfully independent merely by declaring:

```text
I will now examine this independently.
```

The active context may already contain:

- developmental reasoning;
- rejected alternatives;
- Counter-test history;
- preservation rationales;
- expected interpretations;
- and prior conclusions.

Conceptually:

```text
Active Formation State
        ↓
Declaration of Independence
        ↓
Same Active Reasoning State
```

does not create strong operational separation.

Therefore:

> **Judgment Independence cannot be established through intention alone.**

A meaningful state separation is required.

---

# Primary Independence Source

The primary source of independence in Mission 003 is not technical identity difference.

It is:

> **Formation-Process Separation**

Formation-Process Separation means that the reasoning process used for independent examination is meaningfully separated from the specific developmental reasoning process through which the Protocol Candidate was formed.

Conceptually:

```text
Protocol Formation Process
        ↓
SEPARATION
        ↓
Independent Examination Process
```

This separation is intended to prevent the examination from becoming primarily:

```text
Reconstruction
```

or:

```text
Continuation
```

of Mission 002 reasoning.

Instead, the desired relation is:

```text
Existing Protocol Candidate
        ↓
New Examination Relation
        ↓
Independent Judgment
```

---

# Formation-Process Separation Is an Operational Target

Formation-Process Separation is not itself a complete implementation instruction.

The statement:

> Separate the examination from the formation process.

does not explain how the separation is operationally established.

Mission 003 therefore requires safeguards that make the separation credible and traceable.

The Current Baseline identifies two primary safeguards:

1. **Instance-State Separation**
2. **Context Control**

These safeguards operate together.

# 1. Instance-State Separation

## Definition

Instance-State Separation requires the independent examination to occur in a reasoning state that does not simply continue the active developmental state through which the Protocol Candidate was formed.

The relevant distinction is:

```text
Formation Reasoning State
        ↓
continuation
        ↓
Further Reasoning
```

versus:

```text
Formation Reasoning State
        ↓
STATE SEPARATION
        ↓
Fresh Examination State
```

The second structure provides a stronger basis for independent examination.

---

# Why Instance-State Separation Is Necessary

Mission 002 accumulated extensive developmental reasoning.

That reasoning includes more than the final Protocol Candidate.

It includes the paths through which the Protocol was formed, challenged, compressed, restabilized, and internally examined.

If the same active reasoning state immediately performs Mission 003 examination, the examination process may inherit:

```text
Prior Candidate Preferences

+

Rejected Alternatives

+

Preservation Rationales

+

Counter-test Outcomes

+

Developmental Expectations
```

without those influences being explicitly reintroduced.

The result may therefore be:

```text
Formation Process
        ↓
continued
        ↓
Self-examination
```

rather than:

```text
Formation Process
        ↓
separated
        ↓
Independent Examination
```

Instance-State Separation protects against this continuity.

---

# Instance-State Separation Does Not Guarantee Independence

Instance-State Separation is necessary as a safeguard, but it is not sufficient by itself.

For example:

```text
Fresh Instance
        ↓
Full Mission 002
Development History
        ↓
Formation Reasoning
Reintroduced
```

produces:

```text
Instance-State Separation
        ✓

Context Control
        ✗

Formation-Process Separation
        WEAKENED
```

Therefore:

> **Fresh state does not automatically produce independent judgment.**

A separated reasoning state can be reconditioned through the information subsequently provided to it.

This is why Instance-State Separation and Context Control must remain distinct safeguards.

---

# Reasoning-State Continuity Failure

A principal Failure Mode protected by Instance-State Separation is:

> **Reasoning-State Continuity**

This occurs when the examination is performed within the same active developmental state that formed the Protocol Candidate.

Conceptually:

```text
Protocol Formation
        ↓
No State Break
        ↓
"Independent" Examination
        ↓
Continuation of Existing
Reasoning Trajectory
```

The problem is not that the reasoning is necessarily incorrect.

The problem is evidential.

The resulting judgment cannot easily be distinguished from continued internal examination.

Mission 003 exists specifically to introduce a materially different examination relation.

---

# Fresh Reasoning State

A Fresh Reasoning State is a reasoning environment in which the active Mission 002 formation trajectory is not already present as the current reasoning context.

Conceptually:

```text
Mission 002 Formation State
        ↓
State Boundary
        ↓
Fresh Reasoning State
```

A Fresh Reasoning State does not imply:

```text
No Knowledge
```

or:

```text
No Context
```

or:

```text
No Access to the Protocol Candidate
```

Those conditions would risk violating Object Validity.

Freshness refers specifically to separation from the active formation trajectory.

---

# Fresh Chat

A Fresh Chat may provide one implementation of Instance-State Separation.

Conceptually:

```text
Formation Conversation
        ↓
Conversation Boundary
        ↓
Fresh Chat
```

However:

```text
Fresh Chat
        ≠
Independent by definition
```

because formation-derived information can be reintroduced into the new context.

Therefore Fresh Chat is treated as:

> **a possible implementation of Instance-State Separation**

rather than:

> **the definition of Independent Examination**

This distinction must be preserved.

---

# Separate Conversation

Similarly:

```text
Separate Conversation
```

may strengthen state separation, but conversation identity is not itself the target property.

The relevant question remains:

> Does the new reasoning environment meaningfully break continuity with the Protocol formation state?

The technical form used to create that separation is secondary to the functional requirement.

---

# Same Model / Fresh Instance

Mission 003 does not require a different model as a necessary condition.

A configuration such as:

```text
Same Model Family
        ↓
Fresh Instance
        ↓
Controlled Context
        ↓
Independent Examination
```

may provide a materially new judgment relation if the operational safeguards are sufficiently preserved.

Therefore:

```text
Same Model
        ≠
Automatic Independence Failure
```

The relevant issue is not model identity alone.

It is formation-process continuity.

---

# Different Model

A Different Model may provide stronger source separation in some examination designs.

For example:

```text
Mission 002 Model
        ↓
Different Model
        ↓
Mission 003 Examination
```

may reduce certain forms of state continuity.

However:

```text
Different Model
        +
Full Formation History
        ↓
Possible Formation Conditioning
```

still remains possible.

Therefore:

```text
Different Model
        ≠
Independent Examination
```

Different Model is treated as:

> **a possible Independence Strengthener**

rather than:

> **a mandatory Core Condition**

No requirement for model heterogeneity is established by this asset.

---

# Instance Identity Principle

The Current Baseline is therefore:

> **Instance identity may contribute to independence, but independence is determined by the separation relation, not by identity difference alone.**

Conceptually:

```text
Instance Identity Difference
        ↓
Possible Safeguard Strengthening
```

but:

```text
Formation-Process Separation
        ↓
Primary Operational Target
```

This prevents Mission 003 from reducing Independent Examination to a superficial technical criterion.

# 2. Context Control

## Definition

Context Control regulates the information and influence entering the independent reasoning state so that sufficient access to the research object is preserved while unnecessary formation-derived conditioning is restricted.

Its basic structure is:

```text
Context Control
        │
        ├── Preserve
        │   Necessary Object Context
        │
        └── Restrict
            Formation-conditioning Context
```

Context Control is therefore not equivalent to information minimization.

It is selective exposure control.

---

# Context Control Is Not Context Elimination

The goal is not:

```text
No Context
```

because an instance with insufficient access to the Protocol Candidate cannot perform a meaningful examination.

Likewise, the goal is not:

```text
Maximum Context
```

because extensive formation history may condition the independent judgment.

The operational problem is:

```text
Sufficient Object Context
        +
Restricted Formation Influence
```

This directly inherits the Information Exposure Tension established in `01-examination-boundary.md`.

---

# Necessary Object Context

Necessary Object Context includes information required for the reasoning instance to understand and examine the intended research object.

At this stage, this category is defined functionally rather than as a fixed file list.

Conceptually:

```text
Necessary Object Context
        ↓
Information required to
meaningfully examine the
Protocol Candidate
```

This may include information necessary to understand:

- the identity of the research object;
- its intended function;
- its structural organization;
- relevant terminology;
- the examination responsibility;
- and sufficient context for interpreting the Protocol Candidate.

The exact assets used to provide this information are not selected here.

That responsibility belongs to `03-examination-materials.md`.

---

# Formation-conditioning Context

Formation-conditioning Context is information that may cause the examination process to inherit or reconstruct the reasoning path through which the Protocol Candidate was originally formed.

Potential categories include:

```text
Developmental Reasoning

Counter-test History

Rejected Alternatives

Preservation Rationales

Expected Interpretation

Expected Outcome

Prior Validation Reasoning
```

The presence of any single category does not automatically invalidate an examination.

The relevant question is whether its inclusion materially weakens Formation-Process Separation.

Therefore Context Control is not a mechanical prohibition list.

It is an operational safeguard against unnecessary conditioning.

---

# Context Control Applies Beyond the Initial Prompt

Context Control is not limited to the information supplied when the independent instance is first created.

Formation-conditioning information may be reintroduced later through:

```text
Human Follow-up

Additional Documents

Clarifications

Corrective Guidance

Leading Questions

Interpretive Commentary
```

Therefore the relevant scope is:

> **the entire information flow entering the independent reasoning state during the evidence-producing examination process.**

Conceptually:

```text
Initial Context
        +
Subsequent Interaction
        +
Additional Materials
        ↓
Total Examination Context
```

Context Control applies to this total context.

---

# Prior-context Leakage

Prior-context Leakage occurs when a Fresh Reasoning State is established but formation-derived information is subsequently reintroduced.

For example:

```text
Fresh Instance
        ↓
Mission 002 History
reintroduced
        ↓
Formation-conditioning Context
        ↓
Formation-Process Separation
weakened
```

This is not a failure of Instance-State Separation.

The fresh state may have been correctly established.

It is a failure of Context Control.

Therefore:

```text
Prior-context Leakage
        ⊂
Context Control Failure
```

No additional top-level safeguard is required.

---

# Human Reintroduction

Human participation can also become a channel through which formation reasoning re-enters the independent examination environment.

For example:

```text
Independent Examination
        ↓
Human explains why
Mission 002 preserved
a specific structure
        ↓
Formation Reasoning
reintroduced
```

The relevant problem is not Human involvement itself.

The problem is the informational effect of the intervention.

Therefore:

```text
Human Reintroduction
        ⊂
Context Control
```

when Human interaction transfers formation-conditioning information.

The exact Human interaction procedure is not defined here.

That belongs to `04-examination-procedure.md`.

---

# Outcome Framing

Context Control also includes the framing through which the examination task is presented.

For example:

```text
Confirm that this promising
Protocol remains structurally robust.
```

contains a different informational influence from:

```text
Examine the Protocol Candidate
and identify material reasons
for preservation, revision,
or rejection.
```

The first formulation contains stronger outcome-direction information.

Therefore:

```text
Outcome Framing
        ⊂
Context Control
```

when framing materially conditions the expected judgment direction.

This connects directly to the Judgment Steering Failure Mode defined in `01-examination-boundary.md`.

---

# Context Control and Object Validity

Context Control must not be used to maximize independence at the expense of Object Validity.

Overrestriction can produce:

```text
Formation Influence
        ↓
MINIMIZED
```

while simultaneously producing:

```text
Object Understanding
        ↓
INSUFFICIENT
```

Such an examination would not satisfy the Mission 003 boundary.

Therefore Context Control must preserve:

```text
Necessary Object Context
```

even while restricting:

```text
Formation-conditioning Context
```

The balance is structural rather than purely quantitative.

---

# Context Control Principle

The Current Baseline is:

> **Provide what is necessary to examine the research object; restrict what unnecessarily transfers the research object's formation trajectory.**

This principle defines the requirement.

It does not yet select the exact materials.

# 3. Formation-Process Separation

## Definition

Formation-Process Separation is the operational state produced when the independent examination process is meaningfully separated from the developmental reasoning process through which the Protocol Candidate was formed.

It is supported by:

```text
Instance-State Separation
        +
Context Control
```

Conceptually:

```text
Instance-State Separation
        +
Context Control
        ↓
Formation-Process Separation
```

Formation-Process Separation is therefore the central operational target of this Protocol.

---

# What Formation-Process Separation Protects Against

Formation-Process Separation protects against several forms of false independence.

## Continuation

```text
Formation Reasoning
        ↓
same active state
        ↓
Further Reasoning
```

The examination is actually continued development.

---

## Reconstruction

```text
Fresh State
        +
Full Formation History
        ↓
Prior Reasoning Reconstructed
```

The examination appears new but largely reproduces the original reasoning path.

---

## Directed Confirmation

```text
Fresh State
        +
Expected Outcome
        ↓
Confirmation-oriented Judgment
```

The examination is separated technically but not sufficiently separated evaluatively.

---

# Separation Does Not Mean Historical Ignorance

Formation-Process Separation does not require the independent instance to have no knowledge of the research program.

Such a requirement could make examination impossible or distort the research object.

The target is narrower:

> **The instance should not inherit enough of the specific formation trajectory to make its judgment primarily a continuation or reconstruction of that trajectory.**

Therefore:

```text
Research Understanding
        ✓
```

can coexist with:

```text
Formation-Process Separation
        ✓
```

if the information architecture is appropriately controlled.

---

# Separation Is Functional

Mission 003 treats Formation-Process Separation functionally.

The question is not merely:

```text
Was a new chat opened?
```

or:

```text
Was another model used?
```

The question is:

> **Was a reasoning relation established in which the Protocol Candidate could be examined without the original formation trajectory substantially determining the judgment?**

This functional definition permits multiple operational implementations while preserving the same research responsibility.

---

# Relationship to Judgment Independence

Formation-Process Separation is not identical to Judgment Independence.

Rather:

```text
Instance-State Separation
        +
Context Control
        ↓
Formation-Process Separation
        ↓
supports
        ↓
Judgment Independence
```

Judgment Independence remains the higher-order Boundary Property defined in `01-examination-boundary.md`.

02 does not redefine it.

It provides an operational architecture intended to protect it.

---

# Materially New Judgment Relation

The intended result of the Independent Instance Protocol is not guaranteed disagreement.

An independent instance may reach the same conclusion as Mission 002.

Agreement does not prove dependence.

Likewise, disagreement does not prove independence.

The relevant property is:

> **The judgment was produced through a materially new examination relation.**

Therefore:

```text
Same Conclusion
        ≠
Dependence
```

and:

```text
Different Conclusion
        ≠
Independence
```

The evidential significance lies in how the judgment was produced.

---

# Agreement Under Independence

If a materially separated examination process reaches conclusions structurally consistent with Mission 002, that agreement may later contribute to stronger evidence.

However, Mission 003 must not design the Independent Instance Protocol to maximize agreement.

The sequence must remain:

```text
Independent Examination Conditions
        ↓
Judgment
        ↓
Evidence
        ↓
Later Comparison
```

not:

```text
Desired Agreement
        ↓
Examination Design
        ↓
Confirmation
```

The latter would weaken Judgment Independence.

---

# Disagreement Under Independence

Likewise, disagreement is not an examination failure.

A materially independent examination may reveal:

- unsupported assumptions;
- missing conditions;
- structural inconsistencies;
- ambiguous mechanisms;
- boundary defects;
- or reasons for revision.

Such outcomes are legitimate Mission 003 evidence.

Therefore the Independent Instance Protocol must preserve the possibility of:

```text
Preservation

Revision

Rejection

Qualification

Unexpected Observation
```

without precommitting to any one result.

---

# Operational Safeguards Are Not Validation

The presence of:

```text
Instance-State Separation
        +
Context Control
```

does not establish that the Protocol Candidate is valid.

It establishes only that the examination environment has been designed to support a materially independent judgment relation.

Therefore:

```text
Independent Instance Protocol
        ≠
Validation
```

and:

```text
Formation-Process Separation
        ≠
Protocol Confirmation
```

Validation status remains downstream.

---

# Minimal Independent Instance Structure

At the current stage, the minimum operational architecture is:

```text
Existing Formation Environment
        ↓
Instance-State Separation
        ↓
Fresh Reasoning State
        ↓
Context Control
        ↓
Necessary Object Context
preserved

Formation-conditioning Context
restricted
        ↓
Formation-Process Separation
        ↓
Independent Examination Source
```

This structure is the Current Baseline.

It does not prescribe a specific technical platform or model.

# No Absolute Independence Claim

The Independent Instance Protocol does not claim absolute independence.

A reasoning instance may share with earlier instances:

- model architecture;
- training distributions;
- general world knowledge;
- linguistic conventions;
- common reasoning capabilities;
- or other background properties.

Mission 003 does not attempt to eliminate all shared priors.

Its target is narrower:

> **meaningful separation from the specific Protocol formation process being examined.**

Therefore the operational claim is:

```text
Formation-Process Separation
```

rather than:

```text
Absolute Cognitive Independence
```

This narrower claim better matches the available evidence and Mission responsibility.

Therefore model difference is a potentially relevant examination property, but not a substitute for the Core Operational Structure.
